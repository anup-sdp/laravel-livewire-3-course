Yes — this crash course is compatible with Livewire 4, with a small upgrade, not a rewrite. Laravel 11 and PHP 8.2 already meet Livewire 4’s requirements (Laravel 10+, PHP 8.1+). The APIs you use (Component, public properties, wire:model / .live / .debounce, wire:click, wire:submit, $refresh, wire:key, #[Layout], #[Rule], redirect(..., navigate: true), wire:navigate) are still supported.

Livewire 4’s upgrade guide says most v3 class-based apps upgrade with minimal changes. This repo matches that: class + Blade views, no Volt, no custom JS hooks, no published config/livewire.php.

I checked every remote branch (lesson-1 … lesson-12; lesson-11 and lesson-12 are the same commit) plus the current lesson-6 checkout.

composer.json pins "livewire/livewire": "^3.5" from the later lessons. That does not install v4 until you change it to ^4.0.

What will actually break
1. Default full-page layout path (all branches that render pages)

v3 default: resources/views/components/layouts/app.blade.php
v4 default: resources/views/layouts/app.blade.php (layouts::app)

BookList does not set a layout, so after composer require livewire/livewire:^4.0 it will look in the new place. Your layouts stay under resources/views/components/layouts/.

Fix one of these:

Publish config and set 'component_layout' => 'components.layouts.app'
Or move the layout to resources/views/layouts/app.blade.php
Or keep using #[Layout('components.layouts.second')] (already on current CreateBook)
Route::get('/', BookList::class) still works; v4 prefers Route::livewire('/', BookList::class) but does not require it for class components.

2. Unclosed nested tags (lesson-7 through lesson-12) — this is the real app-code break

From lesson-7, book-list.blade.php has:

<livewire:page-header>
From later lessons it is:

<livewire:page-header subtitle="Here's a list of your books...">
In v3 that still rendered. In v4, tags must be closed or the rest of the page is treated as slot content and the nested component may not render:

<livewire:page-header subtitle="Here's a list of your books..." />
That is the only Livewire-syntax change this course needs.

What is fine as-is
wire:model.live.debounce.500ms / .300ms — .live is explicit; the v4 .blur / .change timing change does not apply
wire:model on real <input>s — the new “ignore child events” rule does not apply
wire:key in the @foreach
#[Rule(...)] + $this->validate()
$this->redirect('/', navigate: true) and wire:navigate on nav links
Nested PageHeader with mount($subtitle) — still valid
No wire:scroll, wire:transition modifiers, Volt, $js, or Livewire.hook('commit')
Practical upgrade (when you want to do it)
composer require livewire/livewire:^4.0
Point the layout at components.layouts.app (or move the file)
On lesson-7+, close <livewire:page-header ... />
php artisan optimize:clear and click through list, search, create, delete, and nav
Optional later: Route::livewire(...). You do not need single-file components unless you want them.

Bottom line: this is a small v3 app on a supported Laravel/PHP stack. It is Livewire 4–compatible. The only guaranteed code fix across later branches is closing nested <livewire:...> tags; the layout path is the other thing to handle on every branch that uses full-page components.
